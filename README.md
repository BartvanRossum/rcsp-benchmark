# RCSP Benchmark — Railway Crew Scheduling Problem

A benchmark library of synthetic instances and best-known solutions for the **Railway Crew Scheduling Problem (RCSP)**, accompanying the paper:

> B.T.C. van Rossum, *Branch-and-Price for Railway Crew Scheduling: Benchmark Instances and Computational Study*.

## Instance Overview

The library contains **75 instances** partitioned into three size groups:

| Group  | Instances | Min tasks | Max tasks | Avg. tasks | Avg. connections |
|--------|-----------|-----------|-----------|-----------|-----------------|
| Small  | 25        | 450       | 991       | 704       | 9,420           |
| Medium | 25        | 1,014     | 1,955     | 1,414     | 24,358          |
| Large  | 25        | 2,029     | 3,016     | 2,440     | 53,345          |

Each instance is named `s{S}_t{T}`, where `S` is the number of large stations (where crew members can transfer) and `T` is the number of tasks.

## Problem Description

The RCSP asks for a minimum-cost set of *duties* — sequences of tasks performed by a single crew member in one working day — such that every task is covered at least once.
Each duty must satisfy the following labour rules:
- Start and end at a crew base (depot)
- Total duty length at most 9.5 hours
- Exactly one meal break of at least 30 minutes, with no more than 5.5 hours of continuous work before or after the break

Costs consist of a variable component (1 unit per second of duty time) and a fixed component (equal to 8 hours of variable cost) charged once per duty.

## Generation

Instances are generated by simulating the full railway planning process:
infrastructure network generation, passenger demand, line planning, timetabling, rolling stock scheduling, and crew scheduling input construction.
Details are given in the accompanying paper.

## Feasibility Checker

A standalone feasibility checker is provided as [`checker.jar`](checker.jar). It verifies whether a solution satisfies all constraints and reports the total cost. **Requirements:** Java 11 or higher.

Run it as follows, where the two arguments are the instance folder and the solution file:

```bash
java -jar checker.jar instances/s6_t450 solutions/solution_s6_t450.txt
```

The checker verifies the following constraints:
- Every duty starts and ends at a crew base
- The total duty length does not exceed 9.5 hours
- Every duty contains exactly one meal break of at least 30 minutes, with no more than 5.5 hours of continuous work before or after the break
- Consecutive connections within a duty are compatible
- All tasks are covered by at least one duty

It prints a per-duty feasibility report to stdout followed by the total solution cost.
